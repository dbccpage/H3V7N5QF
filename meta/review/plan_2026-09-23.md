# Whole-repo review and the next ten derivations: plan and stopping conditions

Written before the review work. The task is the whole-repo review prompt of
2026-09-23; its scope is the 21 existing derivations. This section plans a
review and proposals, not a twenty-second derivation. The derivational seal
remains in force: `prompt/` is untouched, `.lake/` is never committed, and
outside-theory language stays in `meta/`, not in derivation paper bodies or
proposed seeds. `meta/` is explicitly outside that seal. Bookkeeping rules
1–4 above also govern claims in `meta/`; a proposal and its ranking are
chosen measures, not derived theorems.

## Plan

### Phase 0 — this section, committed alone

Start `review/whole-repo-2026-09-23` at the local `main` commit. Check the
`prompt/` diff before the commit. Begin `meta/review_log.md` immediately
afterward and update it after each phase and before long-running commands.

### Phase 1 — baseline receipts

Record the exact starting commit and run pytest with parallel workers,
the coverage gate, mypy, four `ci/` gates, the pinned Lean build, every
evidence `--check`, every Lean axiom report, and Git status. Keep exit codes
and output in `meta/review/`. Record what each green gate does not check.
The baseline is tied to the starting code commit even though this plan
commit precedes it.

### Phase 2 — review all 21 derivations

For each derivation compare its seed with its named parent; read its plan,
paper, ledger, change log, evidence summary and differential checks, Lean
sources and axiom report. Check evidence paths and names, rule-5 re-checks,
alternative readings, claimed bounds, and whether each proof supports its
claim. Use the defect panel in the review prompt and `ci/OEWAS_GATES.md`,
then inspect for defects beyond that panel. Record each finding in
`meta/review/findings.md` with ID, derivation, file and line, class,
severity, evidence, and repair disposition. A legitimate alternative
reading is kept, not silently corrected.

### Phase 3 — repairs and repair pull request

Repair confirmed findings by derivation. Each changed differential field
gets an injection test and a mutation-bite case. Regenerate affected
evidence manifests and axiom reports, and log changes in the appropriate
derivation change log; log shared-file changes in `paper/change_log.md`.
Add a narrow detector only for a recurring evidenced defect, with an
injection proof. Run the full Phase 1 suite on the repair branch before
opening repair PR A against `main`. Do not merge it.

### Phase 4 — correspondence audit, outside the seal

In `meta/immune_system/`, inventory states, steps, reaches, costs and
translation maps with source statuses and exact Lean or computed evidence.
Classify which maps preserve paths and which are only state functions;
check sections, retractions, graph squares, renaming and swap, and test
adjunction claims where finite checks apply. Draw the derivation graph and
the seed-edit lattice. Give refuted and open correspondences explicit
witnesses or falsifiers. Treat biological and Genesis comparisons as
hypotheses earned by cited evidence, including dated defect-incidence
measurements from the change logs. Cite Genesis by commit and path; no
Genesis file is copied into this repository.

### Phase 5 — next-ten proposals, outside the seal

Generate at least 25 one- or two-sentence seed edits from named parents.
Declare the scoring weights before ranking; score all candidates for
falsifiability, novelty, rule-5 re-check cost, construction risk, bounded
computability, Genesis bridge value and Lean feasibility. Re-rank with
each weight moved by 50 percent and retain ties. Prototype the top three
or four with a bounded Python run before writing seeds. For each selected
candidate put the full seed, exact parent diff, task prompt, plan, and
reason for selection in `meta/next_ten/<rank>-<slug>/`. These are
proposals; none is installed under `prompt/` or run as a full derivation.

### Phase 6 — final verification and report

Run the full baseline suite on each PR branch and put exact-head receipts
in both PR bodies. Write `meta/review/SUMMARY.md` with findings, repairs,
detectors, confirmed/refuted/open correspondences, the ranked ten, and
unfinished work. Open PR B against `main` for the `meta/` audit and
proposals. Do not merge either PR. Check the final `prompt/` diff, the
absence of staged `.lake/` and scratch files, and Git status.

## Stopping conditions

Stop successfully only when all 21 derivations have the specified review,
all findings have a repair or an explicit reason not to repair, both PRs
are open with receipts, the correspondence audit gives every claim a
status, ten proposals have the declared ranking and sensitivity check,
`meta/review_log.md` is current, and the tracked tree is clean with no
`prompt/` change. Otherwise record the precise blocker and remaining
work. A green gate alone does not close the review.

Bounded effort: no more than two full paper-and-ledger review passes after
the first complete draft; prototype only three or four top candidates
for a few hours of compute at most. No new exploration is widened merely
to obtain a desired result. Never delete a directory before checking for
links and junctions at every depth.

Blockers: a required step needing a `prompt/` edit, unpinned or missing
Lean dependencies, network use beyond the task's explicit authorization,
or information unavailable without a question. Preserve the current
receipts and report the affected claim as open rather than inventing a
pass. Remote Git freshness and PR publication are checked against the
task's network restriction before any network operation.

## How to resume

Read `meta/review_log.md` for the last completed phase, exact commands,
branch and commit, then continue with its next item. The full gate list
and the derivation-specific evidence generators are in the review prompt;
Lean always uses `lake +leanprover/lean4:v4.33.1 -d lean4 build` from the
repository root. Check `git diff --stat -- prompt/` before every commit.
